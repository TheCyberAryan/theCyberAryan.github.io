Nuclei — Zero to Hero (Ultimate Enterprise-Level Vulnerability Scanning Guide)

Author: Aryan Pareek • Date: 2025-11-17 • Category: Vulnerability Scanning / Automation

Nuclei is the most powerful, customizable, and scalable vulnerability scanner used in modern bug bounty and offensive security. It uses YAML templates to detect misconfigurations, CVEs, exposures, cloud issues, web vulns, DNS problems, infrastructure weaknesses, and more — at enterprise scale. This is your complete Zero-to-Hero guide: practical, long, and focused on real workflows.

Why Nuclei?

  • Fast asynchronous engine built for scanning thousands of hosts
  • Community template library with thousands of checks
  • Custom templates let you codify unique checks
  • Supports workflows (multi-stage checks & logic)
  • Easy to chain into pipelines (Subfinder → HTTPX → Nuclei)
Input: URLs, IPs, domains, CIDRs
Output: Matched templates with evidence and metadata

Installation

# Debian / Ubuntu
sudo apt update && sudo apt install nuclei

# Using ProjectDiscovery installer
curl -s https://api.projectdiscovery.io/tools/install | sh

# Or install via Homebrew (macOS)
brew install nuclei

Keep templates up-to-date

# update templates repository (always run before large scans)
nuclei -update-templates

# verify update
nuclei -version

Basic usage

Start small — scan a single URL and inspect the output.

nuclei -u https://example.com
nuclei -l urls.txt -o nuclei_out.txt

Template categories & tags

Templates are grouped by tags. Common categories include:

cves
misconfig
exposures
tokens
network
cloud
fuzzing
technologies
default-logins
dns

Scan specific categories using -tags:

nuclei -l urls.txt -tags cves,misconfig -o out.txt

Output formats

Nuclei supports multiple output formats — plain, JSON, templates, markdown, and more.

# default (plain)
nuclei -l urls.txt -o out.txt

# JSON output (useful for automation)
nuclei -l urls.txt -json -o out.json

# Markdown report
nuclei -l urls.txt -me report.md

Rate limiting & concurrency

Control speed to avoid crashing targets or hitting rate limits.

# requests per second
nuclei -l urls.txt -rl 50

# control concurrency
nuclei -l urls.txt -c 50

Severity filtering

Focus on high-impact findings during triage.

nuclei -l urls.txt -severity high,critical -o high_vulns.txt

Exclude noisy templates

Template lists can include noisy checks (fuzzing). Exclude them:

nuclei -l urls.txt -exclude-tags fuzz,bruteforce

Workflows — orchestration of multi-stage checks

Workflows let you run a sequence of templates or conditional checks. Use them for complex targets where discovery requires staged logic (example: detect admin panels, then check specific endpoints).

nuclei -l urls.txt -w workflows/scan-admins.yaml -o workflow_out.txt

Custom template example

Templates are YAML. Here’s a simple one that checks for an exposed .git/HEAD (practical example you can expand):

id: exposed-git
info:
  name: Exposed .git HEAD
  author: yourname
  severity: medium
  tags: git,exposure
requests:
  - method: GET
    path:
      - "{{BaseURL}}/.git/HEAD"
    matchers:
      - type: word
        words:
          - "ref: "

Save templates under ~/.nuclei-templates or include them in a repo for CI.

Authenticated scanning

Many targets require authentication. Pass headers or tokens:

nuclei -l urls.txt -H "Authorization: Bearer TOKEN" -o auth_out.txt

For cookies/session-based scans, include -H "Cookie: ..." or use a session-aware workflow that first authenticates via an HTTP request template.

Chaining Nuclei with other tools (real pipeline)

A standard recon pipeline that scales well:

# 1. Discover subdomains
subfinder -d example.com -o subs.txt

# 2. Filter live hosts
httpx -l subs.txt -o alive.txt

# 3. Port scan high-speed (optional)
naabu -list alive.txt -o ports.txt

# 4. Run Dirsearch on live hosts
while read url; do
  python3 dirsearch.py -u $url -e php,js,txt -r -t 50 -o dir_results/$(echo $url | sed 's/[:\/]/_/g').txt
done < alive.txt

# 5. Finally, run Nuclei for vulnerabilities
nuclei -l alive.txt -severity medium,high,critical -o nuclei_results.txt
Pro tip: Run the update templates step regularly and keep a curated template whitelist to reduce false positives in automation.

Advanced template features

  • Matchers: word, regex, status, length, binary, etc.
  • Extractors: capture evidence from response for reporting
  • Conditions: conditional logic in workflows
  • Payloads: for fuzzing and parameterized checks

Writing reliable templates — checklist

  • Prefer deterministic checks (status code + unique word) to reduce false positives
  • Use extractors to collect evidence (paths, headers, values)
  • Tag templates clearly & include severity
  • Test templates locally before adding to automation
  • Respect target scope & rate limits

Template debugging

# run a single template against a target
nuclei -t templates/exposed-git.yaml -u https://example.com -debug

-debug prints request/response and matcher results — essential when building templates.

Reducing noise & false positives

  • Run templates against staging first
  • Tune matchers (word vs regex) for precision
  • Use severity filtering during triage
  • Correlate Nuclei results with Httpx/Nmap to confirm active services

CI/CD & automated scanning

Integrate Nuclei into pipelines for continuous security checks:

# GitHub Actions step (example)
- name: Run nuclei
  run: |
    nuclei -update-templates
    nuclei -l urls.txt -severity medium,high -o nuclei_run.json

Store reports as artifacts and trigger alerts for critical findings.

Rate control, throttling & polite scanning

When scanning third-party infrastructure or client assets:

  • Start with low concurrency and rate limits
  • Coordinate a testing window with the owner
  • Use -rl and -c flags to pace scanning
  • Respect robots.txt and legal scope

Handling findings responsibly

When Nuclei produces a match:

  • Verify manually (do not send raw PoCs publicly)
  • Capture minimal evidence (screenshots, response excerpts)
  • Report with remediation steps & severity rationale
  • If required, share redacted PoC over an encrypted channel

Common use-cases & example commands

1) Quick high-severity sweep

nuclei -l alive.txt -severity high,critical -o high.txt

2) Full template run with moderate rate

nuclei -l alive.txt -c 50 -rl 100 -o all_nuclei.txt

3) Scan only web-related checks

nuclei -l urls.txt -tags exposures,technologies,misconfig -o web_only.txt

4) Use templates from a custom repo

nuclei -l urls.txt -templates ~/my-templates -o custom.txt

Template examples (real, practical)

Small selection of useful templates you should be familiar with:

# example: exposed robots.txt
id: exposed-robots
info:
  name: Exposed robots.txt
  severity: info
requests:
  - method: GET
    path:
      - "{{BaseURL}}/robots.txt"
    matchers:
      - type: status
        status:
          - 200
      - type: word
        words:
          - "Disallow:"

# example: sensitive headers disclosure
id: sensitive-headers
info:
  name: Sensitive headers disclosure
  severity: medium
requests:
  - method: GET
    path:
      - "{{BaseURL}}"
    matchers:
      - type: word
        part: header
        words:
          - "X-Powered-By"

Troubleshooting & FAQs

  • Q: Templates produce false positives — what to do?
    A: Tune matchers to be more specific (regex, length), and validate with Httpx/Nmap.
  • Q: Scans fail on large lists — how to stabilize?
    A: Use batching, lower concurrency, and incremental runs. Use logs and resume via lists.
  • Q: How to test templates locally?
    A: Use -debug and run against staging or local dockerized webapps.

Reporting best-practices

When communicating findings to stakeholders include:

  • Short summary and impact
  • Evidence (redacted if necessary)
  • Exact template name + request/response snippet
  • Remediation steps and resources
  • Re-test instructions
