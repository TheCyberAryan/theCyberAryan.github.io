Race Condition Vulnerabilities — When Timing Becomes a Bug

Race conditions happen when an application performs multiple operations in parallel and doesn’t handle them safely.

In simple words:

“If I send the same request many times very fast, the system gets confused and gives me extra benefits.”

Real-World Examples

  • Buying the same coupon multiple times even though it should be “one per user”.
  • Transferring more money than balance using parallel requests.
  • Creating multiple accounts with a single-use invite code.

How Attackers Exploit It

  • Send 10–100 parallel requests at the same time (using Burp Intruder, Turbo Intruder, custom scripts).
  • Target endpoints that change account balance, points, coupons, stock, etc.

Key Signs of a Race Condition

  • Same action allowed multiple times in parallel.
  • Inconsistent responses.
  • Balance/points changing incorrectly.

Defence

  • Use proper locking in backend logic.
  • Perform atomic operations at database level.
  • Validate state again after the operation (e.g., check if coupon already used).
