📂 PATH TRAVERSAL — Escaping Folders Like a Cyber Ninja

Path Traversal is basically the vulnerability where a website says:

“Here, choose a file from this folder.”

And you say:
“Okay… but what if I go OUTSIDE the folder?”

And the server, being an absolute people-pleaser, replies:
“Sure boss, take the whole filesystem.”

In one clean cyberpunk sentence:
Path Traversal = Using ../ to climb out of restricted directories and read sensitive files.

💀 Why Path Traversal Exists (Sarcastic Truth)

Because developers assume users won’t manually tamper with URLs. Buddy… the website is literally sitting on the public internet. We WILL tamper with URLs. With love. And curiosity. And Burp Suite.

They write things like:

GET /download?file=report.pdf

And backend logic is:

open("/var/www/app/reports/" + user_input)

Meanwhile you’re like: 

../../../../etc/passwd

And the server is like:

“Yes chef.”

🎉 Congratulations, you just performed Path Traversal.
You are now casually browsing the server’s internal files like a tourist.

🎯 Where Path Traversal Loves to Hide

ANY feature involving file paths is immediately SUS:

  • ?file= – 90% chance vulnerability
  • ?path=
  • ?template=
  • ?image=
  • ?download=
  • Backup import features
  • Log viewers
  • Custom theme / template pickers
If the app lets you choose “a file”… You can probably choose “every file”.

🧪 The Famous Payloads (The “../” Family)

Basic Linux file read:

../../../../etc/passwd

URL encoded:

..%2f..%2f..%2f..%2fetc%2fpasswd

Double encoded (for wannabe “smart” filters):

..%252f..%252f..%252f..%252fetc%252fpasswd

Windows vibes:

..\..\..\..\windows\win.ini

🔍 Realistic Path Traversal Attack (Step-by-Step)

User requests:

/download?file=invoice_102.pdf

Attacker requests:

/download?file=../../../../etc/passwd

If you receive:

root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
You just won the “Critical Severity Vulnerability” jackpot.

🧬 Filter Bypasses (Because Developers Try… Poorly)

Common developer defenses:

  • Block literal string ../
  • Block \..
  • Allow only .pdf
  • Decode input once

Your responses:

  • ....// → Normalizes to ../
  • %2e%2e%2f
  • %252e%252e%252f
  • ../../etc/passwd%00.pdf (older systems)
Fun Cyber Tip:
You don’t escape filters. You outsmart them.

💣 Escalation: From Path Traversal → Total Pwn

After proving the bug with /etc/passwd, move to:

  • .env files
  • config.php (DB creds)
  • settings.json
  • API keys
  • Source code files

One leaked DB password can turn your file-read bug into a full takeover.

🔐 How Websites Should Fix (But Rarely Do)

  • Use strict allow-lists
  • Resolve real path and ensure it stays inside allowed directory
  • NEVER concatenate raw input into file paths
  • Apply sandboxing / chroot where possible
Most developers try to “sanitize” path traversal.

You don’t sanitize it.
You eliminate user-controlled paths entirely.

🎯 Final Verdict

Path Traversal is:

  • dead simple
  • fun to exploit
  • easy to escalate
  • and a goldmine in bug bounties

All because one little ../ can turn you from User → Superuser → Server Explorer.
